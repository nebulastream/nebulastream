What Retain does, and where it goes

SELECT id + 1 AS a, CASE WHEN val > 30 THEN val ELSE NULL END AS b
FROM (SELECT * FROM events UNION ALL SELECT * FROM events2) WHERE id < 3

One branch of the union (events), with data flowing from top to bottom. Each pill is a field of the row that an operator passes on; $n is its position, by which the operators above refer to it. The other two branches (the two physical sources of events2) look the same.

Where Retain comes from

1. Calcite's logical plan has two projections

This is the plan before the physical step (planner step "types made explicit for NebulaStream"). A LogicalProject computes a list of expressions over its input row; its output row is exactly that list, and the operator above it refers to the output by position.

LogicalProject(a=[+($0, 1)], b=[CASE(>($1, 30), $1, null)])     <- the query's SELECT list
  LogicalUnion(all=[true])
    LogicalProject(id=[$0], val=[$1])                         <- SELECT * narrowed to the columns used
      LogicalFilter(condition=[<($0, 3)])
        LogicalTableScan(table=[[events]])
    LogicalProject(id=[$0], val=[$1])
      LogicalFilter(condition=[<($0, 3)])
        LogicalTableScan(table=[[events2]])

The lower projections come from SELECT *: Calcite's field trimmer removed ts, which the outer query never reads.

2. The projection rule lowers each LogicalProject into maps and a Retain

NesPhysical.ProjectionRule, one of the converter rules that turn Calcite's logical operators into ours. Our Map can only append one computed field, so per expression of the projection: a plain column reference ($0) needs no operator, the field is simply kept; a computed value becomes a Map that appends it. Then a Retain lists the positions that form the projection's output row.

a = $0 + 1, b = CASE … (input row: ID, VAL)

↓

row$0ID$1VAL$2F0$3F1
↓

row$0F0$1F1
= the projection's output row (a, b)

id = $0, val = $1 (input row: ID, VAL, TS)

Both are plain column references: no Map.
Retain [0, 1]
row$0ID$1VALTS
= the projection's output row (id, val)

(The union rule adds one more case: if a union input has a field of another type than the union, it casts it with a Map and uses a Retain to put the cast field in its place. Not needed in this query.)

3. Why it is needed, and why it disappears

Without the Retain, the operators above a projection would see the input row with the computed fields appended, at other positions than the plan says. The Retain keeps the positions right while Calcite plans. But no engine operator can drop fields except the Emit at the end of a pipeline, so Pipelines.finish folds each Retain into that Emit and renumbers the field references in between. The rest of this page shows that for one branch.
